## Native Universal Search architecture decision — September 21, 2026

The authoritative Project Specification now assigns **core Universal Search ownership to GoreeCloud Launcher**. This is an approved planned architecture and authority boundary, not a claim that the current Development runtime has already completed the migration.

Launcher owns the user-facing Universal Search UI, native provider framework, core local indexing required for the Launcher experience, result aggregation/ranking, permission-aware categories, recents/history, commands, shortcuts, contextual actions, and standardized provider APIs. Core Universal Search must remain usable when GoreeCloud Index and GoreeCloud Search are absent, disabled, unavailable, or not production-ready.

GoreeCloud applications and platform services should register searchable resources, actions, shortcuts, commands, and supported metadata through versioned Launcher provider contracts. Those contracts must define identity, resource types, authorization requirements, result/action schemas, ranking metadata, freshness, privacy, offline behavior, cancellation/timeouts, failure isolation, and compatibility/versioning.

GoreeCloud Search and GoreeCloud Index remain separately developed systems. Once stable, Search may integrate as an optional advanced search/query/discovery backend and Index may integrate as an optional scalable indexing/retrieval backend. Neither service is a prerequisite for core Launcher Universal Search and neither owns the Launcher user-facing Universal Search authority.

Historical PRs and current source evidence that describe GoreeCloud Index as universal provider/ranking authority remain valid provenance for those exact Development revisions until deliberately migrated. They must not be interpreted as the controlling future architecture.
