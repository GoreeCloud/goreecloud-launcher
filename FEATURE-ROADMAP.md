## Native Universal Search architecture and current implementation

The authoritative Project Specification assigns **core Universal Search ownership to GoreeCloud Launcher**. Launcher owns the user-facing Search UI, native provider framework, core local indexing required for the Launcher experience, result aggregation/ranking, permission-aware categories, recents/history when implemented, commands, shortcuts, contextual actions, and standardized provider APIs. Core Search must remain usable when GoreeCloud Index and GoreeCloud Search are absent, disabled, unavailable, or not production-ready.

The Development line now includes a distinct Launcher-owned Search surface, trusted local actions, installed-app Search, deterministic ranking, fail-soft aggregation, cooperative cancellable asynchronous provider execution, rendered query replacement, versioned provider registration metadata/catalog evaluation, privacy-first automatic-local versus explicit-user-handoff policy, and a UI-facing presentation model that separates already-ranked application matches from Launcher action/settings results without introducing a second ranking system.

GoreeCloud applications and platform services may register searchable resources, actions, shortcuts, commands, and supported metadata only through versioned, explicitly governed provider contracts. Those contracts must define provider identity, resource/action schemas, authorization and privacy requirements, freshness, ranking metadata, offline behavior, cancellation/timeouts, failure isolation, query-retention behavior, and compatibility/versioning. Provider metadata and registration do not grant Android permission, GoreeCloud authorization, user consent, profile access, or external-provider trust. PR #195 consumes the provider-control model only to build descriptive UI-facing groups; it does not grant permission to transmit a typed query.

GoreeCloud Search and GoreeCloud Index remain separately developed systems. Once stable, Search may integrate as an optional advanced search/query/discovery provider/backend and Index may integrate as an optional scalable indexing/retrieval provider/backend. Neither is a prerequisite for core Launcher Universal Search and neither owns the Launcher user-facing Search authority.

Historical revisions that describe GoreeCloud Index as Universal Search provider/ranking authority remain valid provenance for those exact revisions; they do not control the current architecture.

## Search inspiration translation — September 22, 2026

Owner-provided launcher-search screenshots are treated as interaction inspiration, not a UI or asset set to clone. The useful concepts are:

- visually prioritize direct app matches;
- keep Launcher actions and Settings results structured and scannable below app matches;
- provide a clear provider/source manager with enable/disable state, deterministic ordering, provider information, and an add/discovery affordance only after an approved trust boundary exists;
- support an explicit `Search with`-style handoff for optional providers rather than silently broadcasting every typed query;
- keep the final presentation Glaze-native, local-first, free of sponsored ranking, and consistent with Launcher accessibility and privacy requirements.

PR #188 establishes the execution/control policy needed before optional providers can be surfaced safely. PR #195 adds the non-invoking presentation-model foundation needed to separate direct app results from Launcher action/settings results and to expose only enabled explicit-handoff providers as descriptive future `Search with` options. A network, remote, retaining, authorization-requiring, or third-party provider must not receive an automatic typed query merely because it is registered, enabled, or displayed.

## Planned next capabilities

- Render the PR #195 presentation structure in the **Glaze-native Universal Search surface** so direct application matches are visually distinct from Launcher actions/settings while preserving `LauncherUniversalSearch` ordering and accessibility semantics.
- Render a **Glaze-native Universal Search provider/source manager** using the PR #184/#188 policy foundations and PR #195 handoff presentation model. Show source name, enable/disable state, deterministic order, invocation mode, and privacy information. Keep current local core providers automatic/offline.
- Persist provider enable/order preferences only through an explicitly versioned preference change with safe migration/backup semantics. Preserve the distinction between first-run defaults and an explicit user choice to disable optional sources.
- Add explicit `Search with` handoff execution only after provider-specific trust, authorization, privacy, and failure contracts are accepted. Network, remote, retaining, authorization-requiring, and third-party providers must remain user-invoked and must not receive automatic typed-query fan-out.
- Add external provider discovery/registration transport only after the trust boundary, compatibility model, revocation behavior, package/profile isolation, and user-facing provider information are accepted.
- Evaluate partial/streaming result presentation only if provider/runtime evidence shows it materially improves interaction quality; do not invent timing budgets without measured Launcher evidence.
- Define privacy-preserving recents/history/context semantics before storing or using query/activity history. Keep core Search useful with those features disabled.
- Add richer local Search sources, shortcuts, commands, settings/actions, and permission-aware result categories before optional GoreeCloud Search / GoreeCloud Index integrations.
- Validate User Apps / Work Apps on representative personal/work/Shelter configurations, including profile creation/removal, availability, package install/update/remove/suspend, same-label apps, launch correctness, isolation, and no cross-profile leakage.
- Collect representative physical-device/default-HOME performance, accessibility, and power evidence against the current source-bearing runtime; use those measurements to tune icon warming, transitions, Search latency, drawer profile presentation, and Compose state behavior.
- Verify Quickstep/Recents compatibility on the supported GoreeCloud/LineageOS system boundary.
- Continue workspace capability behind the Phase A gate: mature cross-page drag/drop, folders, widgets, shortcuts, sub-grid positioning, notification badges, gestures, icon packs, and recovery-safe edit semantics.
- Complete Launcher-specific GLAZE UI V1.6 rendered/accessibility/adaptive/performance/rollback/Human Visual Excellence acceptance and evidence-backed integration for all applicable Integral Platform Systems.
