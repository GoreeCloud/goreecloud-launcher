## Native Universal Search architecture decision — September 21, 2026

The authoritative Project Specification assigns **core Universal Search ownership to GoreeCloud Launcher**. Launcher owns the user-facing Universal Search UI, native provider framework, core local indexing required for the Launcher experience, result aggregation/ranking, permission-aware categories, recents/history, commands, shortcuts, contextual actions, and standardized provider APIs. Core Universal Search must remain usable when GoreeCloud Index and GoreeCloud Search are absent, disabled, unavailable, or not production-ready.

GoreeCloud applications and platform services should register searchable resources, actions, shortcuts, commands, and supported metadata through versioned Launcher provider contracts. Those contracts must define identity, resource types, authorization requirements, result/action schemas, ranking metadata, freshness, privacy, offline behavior, cancellation/timeouts, failure isolation, and compatibility/versioning.

GoreeCloud Search and GoreeCloud Index remain separately developed systems. Once stable, Search may integrate as an optional advanced search/query/discovery backend and Index may integrate as an optional scalable indexing/retrieval backend. Neither service is a prerequisite for core Launcher Universal Search and neither owns the Launcher user-facing Universal Search authority.

Historical revisions that describe GoreeCloud Index as Universal Search provider/ranking authority remain valid provenance for those exact revisions; they do not control the current architecture.

## Planned next capabilities

- Complete the next bounded Universal Search contract tranche: versioned provider registration/compatibility and explicit provider authorization/privacy metadata, without adding network dependence or silently broadening data authority.
- Evaluate partial/streaming result presentation only if provider/runtime evidence shows it materially improves interaction quality; do not invent timing budgets without measured Launcher evidence.
- Define privacy-preserving recents/history/context semantics before storing or using query/activity history. Keep core Search useful with those features disabled.
- Add richer local Search sources, shortcuts, commands, settings/actions, and permission-aware result categories before optional GoreeCloud Search / GoreeCloud Index integrations.
- Validate PR #182's User Apps / Work Apps drawer behavior on representative personal/work/Shelter configurations, including profile lifecycle changes and private-space policy; correct source only from observed evidence.
- Collect representative physical-device/default-HOME performance, accessibility, and power evidence against current source-bearing runtime; use those measurements to tune icon warming, transitions, Search latency, drawer profile presentation, and Compose state behavior.
- Verify Quickstep/Recents compatibility on the supported GoreeCloud/LineageOS system boundary.
- Continue workspace capability only behind the Phase A gate: cross-page drag/drop, folders, widgets, shortcuts, sub-grid positioning, notification badges, gestures, icon packs, and recovery-safe edit semantics.
- Complete Launcher-specific GLAZE UI V1.6 rendered/accessibility/adaptive/performance/rollback/Human Visual Excellence acceptance and evidence-backed integration for all applicable Integral Platform Systems.
