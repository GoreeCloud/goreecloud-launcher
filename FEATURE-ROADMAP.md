## Launcher experience expansion — September 12–13, 2026

The detailed capability set is documented in `LAUNCHER-EXPERIENCE-EXPANSION.md`. It incorporates the new launcher-reference direction while keeping the distinction between current Development implementation and future planned scope.

### Active implementation tranches

- Persistent Grid/List app drawer presentation is implemented on Draft PR #96. Grid remains the default and fail-safe mode; List is lazy-rendered and reuses existing local search, launch/manage behavior, icon cache, and icon-scale controls.
- PR #96 exact head `b4d95027cb9fda979919f3caa21b819f6c7595c3` passed Android CI run `34735922867` attempt 2, including both `validate` and Android 16 runtime jobs. This is automated Development evidence only, not physical-device or release acceptance.
- Draft PR #97 exact head `0b74f449c4a08eb9524df84080dd8fcb34d04075` passed Android CI run `34759501859`. It adds persistent A→Z/Z→A local installed-app ordering, top/bottom drawer search placement, and an alphabetical fast-navigation rail that works across Grid and List. The rail exposes only sections present in the current local inventory and is hidden while a search query is filtering results.
- Drawer layout, sort order, and search-position keys are deliberately outside portable backup/recovery v1. A future snapshot format must version these presentation settings explicitly rather than silently broadening the current seven-field recovery contract.
- Draft PR #110 is stacked on current Draft PR #109 and adds a persistent Compact drawer mode using the existing lazy grid, configured drawer columns, icon scaling, labels, local installed-app search, local sorting, alphabetical fast navigation, and shared icon-cache path. It adds no new inventory, Index, network, telemetry, account, synchronization, or backup/restore authority. Exact-final-head CI remains the acceptance gate for this Development tranche.
- Draft PR #98 exact head `6d35ac144e96b6fc61c3d969e2e7af442291099e` passed Android CI run `34760609799`. It adds an explicit Home overview/edit surface with ordered page cards, bounded count previews, selection, non-drag Earlier/Later reordering, page creation, and confirmed deletion for completely empty non-primary pages only.
- PR #98 page mutation controls obey the existing layout lock and fail closed when the canonical primary Home page is not rank zero. The canonical primary page cannot be moved or deleted. Room remains the authoritative post-cutover workspace source; the overview does not infer or claim authoritative cell coordinates from its previews.
- Draft PR #99 final synchronized head `0a6e24c4b95df16a5372487666267348cf5689bb` passed Android CI run `34762388664` / #355. It provides explicit checkbox-based multi-select for currently resolved installed applications on a secondary Home page, deterministic current-page ordering, secondary-page-only destinations, layout-lock and primary-page guards, and stale-selection reconciliation.
- Draft PR #100 implementation head `2c48749eed203842968b5ce59a0aaec1745c3123` passed Android CI run `34762929330` / #356, including normal validation and Android 16 runtime coverage. It replaces PR #99's sequential group movement with an all-or-nothing Room batch transaction. Every target placement is planned before writing; the complete HOME snapshot is rechecked inside the transaction; all selected item rows are committed together; and complete readback is verified before the transaction may succeed.
- PR #100 also introduces an opaque exact-state rollback checkpoint and rollback transaction. Rollback succeeds only while the complete HOME page/item state still equals the batch's applied snapshot. Any intervening HOME mutation makes rollback fail closed. PR #100 synchronized/copy-corrected head `febefe0da2554e79449a0b5faf041679bdf96cf9` passed Android CI run `34763563436` / #359 after the Android 16 runtime job passed on rerun.
- PR #100 does not change Room entities or schema version, does not broaden portable backup/recovery v1, and keeps the canonical primary HOME page outside the secondary spatial batch-edit path.
- Draft PR #101 final synchronized head `2759260d3e821d3b1b5eb538367784b1d014e709` passed Android CI run `34766428420` / #368, including `validate` and the Android 16 runtime suite. It exposes **Undo last move** in Home overview/edit mode, stores exactly one successful batch checkpoint in activity-local memory, replaces that checkpoint after a newer successful batch, disables Undo while layout lock is active, returns to the source page after a successful rollback, and clears/refuses the checkpoint when exact-state rollback safety can no longer be proven.
- PR #101 intentionally does not persist the checkpoint in DataStore, Room, portable backup, or Everkeep. Activity recreation and process death discard it. The same consumed rollback checkpoint is covered by runtime testing and cannot be replayed after successful restoration. Durable multi-step undo/redo remains separately planned.
- PR #101 also increases the existing hosted-emulator lifecycle/reactivity test settle bound from 15 to 30 seconds after repeated timeout-only flakes on otherwise-green heads. That change is test reliability hardening and is not startup-latency or performance acceptance.
- Draft PR #104 implementation head `5429453ae58d794a11ec5e18b889cfd66ebae74c` passed Android CI run `34767635221` / #369, including both `validate` and `room-runtime-emulator`. It adds explicit **Compact apps** cleanup for eligible secondary Home pages. Compaction preserves authoritative page-item rank order, deterministically packs 1×1 apps into row-major cells within the current Home grid, refuses unsupported shortcuts/folders/widgets/non-1×1 items, refuses insufficient capacity without cross-page spill, and commits all changed rows transactionally only if the complete HOME snapshot still matches the planned state.
- PR #104 clears the existing one-level batch-move Undo checkpoint only after a successful compaction because compaction is a distinct workspace mutation. Room entities/schema and portable backup/recovery v1 remain unchanged; primary Home compaction is protected.
- GoreeCloud Index remains the canonical universal search/index/provider/ranking authority. Drawer sorting and alphabetical navigation apply only to Launcher's local Android `LauncherApps` inventory.

### Planned next capabilities

- Category, Search-first, and optional paged drawer presentation modes after PR #110 Compact validation.
- Explicit custom ordering plus recent/frequent views only if locally derived, transparent, user-controlled, and free of behavioral tracking.
- Expanded one-handed reachability controls and transition tuning after the current search-position implementation is validated.
- Complete Launcher-specific acceptance against current Stable Glaze UI `1.5.1`, including rendered visual quality, accessibility, adaptive phone/tablet/foldable posture, performance/power, rollback, and representative-device evidence; PR #109 source adoption does not satisfy those application-local gates.
- Durable multi-step undo/redo and process-death-safe edit history only after lifecycle, migration, privacy, recovery, and Everkeep-appropriate semantics are explicitly designed and accepted.
- Direct group drag workflows and broader edit-mode ergonomics on top of the atomic batch, one-level Undo, explicit compaction, and non-drag foundations.
- Folders, smart folders, collections, categories, tags, locked/private organizational surfaces, and explicit user-approved smart reorganization.
- Android `AppWidgetHost`, searchable widget gallery, resize/configuration, widget stacks, first-party Glaze Cards, and provider crash containment.
- Expanded long-press actions, Android shortcuts, app info/uninstall-disable handoff, privacy controls, and evidence-backed Wardveil status.
- Independent Home/Drawer/Folder/Dock density and styling, icon/label overrides, wallpaper palettes, motion/blur/transparency/accessibility controls.
- Launcher Profiles for Personal, Work, Travel, Focus, Minimal, and user-defined layouts.
- A future Glaze Shelf for user-pinned actions, media controls, temporary tasks, and compact first-party cards.
- Work profile/private-space correctness and no cross-profile leakage through search, suggestions, widgets, previews, or backup.
- Phone/tablet/foldable/posture-aware layouts, keyboard/D-pad/Switch/TalkBack accessibility, and physical-device performance/power acceptance.
- Privacy Shield, Wardveil Security, and Everkeep integrations that remain evidence-backed and fail closed where authorization or recovery proof is required.

GoreeCloud Index remains the canonical universal search/index/provider/ranking authority throughout this expansion. Launcher continues to own narrow local installed-app filtering and Launcher-specific presentation/organization only.
