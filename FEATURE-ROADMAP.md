### Native Universal Search architecture and current implementation — September 22, 2026
- GoreeCloud Launcher owns the user-facing Universal Search experience, native provider framework, core local indexing required for the Launcher experience, result aggregation/ranking, permission-aware categories, actions, commands, shortcuts, recents/history when implemented, contextual behavior, and standardized provider APIs. Core Universal Search must remain usable without GoreeCloud Index or GoreeCloud Search.
- The current Development line includes the distinct Launcher-owned Universal Search surface, trusted local Launcher actions, installed-app search, deterministic ranking, fail-soft provider aggregation, cooperative cancellable asynchronous provider execution, rendered async query replacement, User/Work result identity, versioned provider registration metadata/catalog evaluation, privacy-first automatic-local versus explicit-user-handoff policy, and the PR #195 UI-facing presentation model. PR #198 adds the versioned provider-preference serialization boundary: provider enablement and explicit order can now be encoded deterministically without storing typed queries, results, history, usage/frequency signals, credentials, authorization grants, or provider payloads. The contract fails closed on malformed structure, provider-ID encoding, malformed UTF-8, blank IDs, duplicates, and unsupported future versions.
- GoreeCloud applications and platform services may register searchable resources, actions, shortcuts, commands, and supported metadata only through versioned, explicitly governed provider contracts defining provider identity, resource/action schemas, authorization and privacy requirements, freshness, ranking metadata, offline behavior, cancellation/timeouts, failure isolation, and compatibility/versioning. PR #184 implements descriptive provider contract metadata and catalog compatibility; PR #188 adds deterministic enable/order normalization plus automatic-local versus explicit-user-handoff classification; PR #195 consumes those controls only to build descriptive UI-facing result/handoff groups; PR #198 adds a versioned serialization contract for provider-control identity/order state. None of these layers grants Android permission, GoreeCloud authorization, user consent, profile access, external-provider trust, or permission to transmit a typed query.
- GoreeCloud Search and GoreeCloud Index remain separately developed systems. They may later integrate as optional advanced providers/backends without transferring Launcher Universal Search ownership and without becoming prerequisites for core local Launcher search.
- Historical Index-oriented revisions remain valid provenance for those exact Development revisions only. Actual DataStore persistence/migration of the PR #198 provider-preference payload, portable backup/recovery adoption, a rendered provider-management surface, external provider discovery/registration transport, provider-specific consent and permission flows, explicit external query handoff execution, additional local sources, richer result/action schemas, partial or streaming result presentation, recents/history/context, and optional Search/Index providers remain open.
### Planned next capabilities
- Continue the Launcher-owned Universal Search provider fabric beyond installed apps and trusted local actions. PR #188 provides the privacy-first execution/control policy, PR #195 provides the UI-facing grouping model, and PR #198 now provides the versioned persistence payload boundary for provider enable/order state without storing typed queries or history. Next bounded work should wire that contract into safe DataStore migration and portable backup/recovery semantics and render a Glaze-native provider/source manager with clear source information, enable/disable state, deterministic ordering, invocation mode, and privacy details. Preserve first-run defaults versus an explicit empty optional-provider selection. A later explicit Search-with-style handoff may invoke network, remote, retaining, authorization-requiring, or third-party providers only after their trust/consent contracts are accepted; those providers must never receive automatic typed-query fan-out merely because they are enabled.
- Validate User Apps and Work Apps on representative hardware with a real secondary/work/Shelter profile: profile creation/removal, availability/unavailability, package install/update/remove/suspend, same-label apps across profiles, isolation, switching, launch correctness, and no cross-profile leakage.
- Perform representative-device performance review of the PR #180/#182 source line: Home-to-drawer latency, icon readiness, first-open versus warm-open behavior, scroll/page smoothness, frame timing/jank, memory pressure, battery/power impact, and OEM-specific behavior. Emulator transition-performance evidence remains diagnostic only.
- Extend workspace editing from the PR #176/#177 foundations into mature cross-page drag/drop, explicit page transfer targets, folders and smart folders, broader organization, group actions, and process-death-safe undo/recovery.
- Add Android AppWidgetHost, searchable widget gallery, resize/configuration, widget stacks, first-party Glaze Cards, and provider crash containment.
- Add user-defined categories, tags, collections, explicit custom ordering, and locally derived recent/frequent views only when transparent, user-controlled, and free of behavioral tracking.
- Complete Launcher-specific GLAZE UI V1.6 rendered, accessibility, adaptive phone/tablet/foldable, reduced-effects, contrast, scalable-text, performance/power, rollback, and Human Visual Excellence acceptance.
- Complete portable backup/restore coverage for current Launcher preferences and workspace behavior while preserving compatibility with legacy stored keys whose UI may no longer be rendered.
- Complete evidence-backed runtime integration for GoreeCloud Manager, Privacy Shield, Wardveil Security, Everkeep, Glaze UI, GoreeCloud Mesh, GoreeCloud Identity, GoreeCloud Policy, and GoreeCloud Observability while preserving authority boundaries.
- Validate Quickstep/Recents and default-HOME behavior on representative Android and LineageOS devices without inferring acceptance from emulator-only evidence.
- Validate keyboard, D-pad, Switch Access, TalkBack, large-text, RTL/localization, reduced-motion/transparency, contrast, and touch-target behavior across Home, Universal Search, drawer profile tabs, Settings, and editing surfaces.
- Add pinned/dynamic shortcuts and richer Android package-state handling through platform-authoritative APIs and explicit lifecycle tests.
- Keep advanced intelligence local-first/private-by-default and defer suggestions, smart folders, natural-language assistance, and optional remote providers until their authority, privacy, failure, offline, and user-control contracts are accepted.
- Preserve Development-only artifact provenance and complete rollback/recovery, protected signing, reproducible packaging, Release Candidate qualification, and production approval only after all applicable acceptance gates pass.
- Keep this Drive roadmap, repository FEATURE-ROADMAP.md, Project Specification, Change Log, issue #80, and GoreeCloud Tasks Management materially synchronized after each material implementation or acceptance change.
